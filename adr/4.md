### Flush memtable to level 0 

Memtable flushes all current entries to a file at level 0.

Will require a scanner for the memtable. Initial scanner will start at head of level 0 and continue through to the end of the skiplist

Scanner will be an state machine instance. moved forward by next, key, value, release.

Scanner will use the sequence number at the time it is created and will not return any values after that sequence number.

memtable will flush when keys + value stored exceeds n - file overhead.

memtable will be replace with an empty one at the start of each flush.

Storage component will interface with the file system, read writes etc.

DB layer will encode all data and uphold invariants

After written to disk, the db layer will retain a file handle and metadata of files in the order created

Data file structure:
- made up of 4kb data blocks of end to end key/value data
- after all datablocks, there is an index block + footer. 
- footer at end of file will point to index block
[ Data blocks 4096b
    [key len uint16][key n bytes][value len uint16][value n bytes]...
    
    [checksum uint32 (at end of block)]
]
....
[ Index block n bytes
    [key len uint16][lastkey uint64][datablock offset]...

]
[ Footer
    [index block offset uint64] [index block length uint64][magic number uint16]
]

Manifest will be name of db layer's in memory representation of stored data files 

### External Contract
Internal only

### Black Boxing
main routine DB -> replaces Memtable 
background routine for flush DB/scanner -> Storage -> disk -> updates Manifest w/ new file

### Invariants
1. Scanner will only return values LTE the sequence number that it started
1. Memtable kv data stored will not exceed 10MB
1. Entries on disk are always sorted
1. DB will maintain representation of all data files on disk

### Build Sequence
1. Scanner state machine:Next, key, value, release
1. DB serialize memtable into data pages and index blocks
1. Storage durably writes to disk
1. DB updates Manifest
